Problem Statement

1

Time‑consuming information access

Students search across multiple PDFs for specific concepts—opening files, trying different keywords, and scanning pages repeatedly. This manual effort grows with the collection and interrupts focused revision.

The problem is not a lack of information, but the effort to locate the relevant part.

2

Incomplete evidence from single‑method retrieval

Keyword search misses paraphrased explanations; semantic search may overlook exact names or abbreviations. Either method alone fails to retrieve all relevant passages consistently.

A single retrieval path cannot cover the full range of relevant evidence.

3

Lack of verifiable source grounding

General AI assistants often answer without citing specific documents or page numbers, making verification difficult. Responsible educational AI requires transparency and traceability.

Answers must show their sources and indicate when evidence is insufficient.

Need: a system that searches personal lecture collections using natural‑language questions, combines lexical and semantic retrieval, and generates concise answers with citations for easy verification.

Project Objectives

01

Develop a web-based lecture Q&A system

Provide an accessible interface for uploading, viewing, selecting, and deleting lecture PDFs; managing conversations; and submitting natural-language questions—without requiring knowledge of retrieval or machine-learning tools.

02

Implement a hybrid RAG pipeline with source citations

Process lecture PDFs to create sentence embeddings stored in FAISS, combine BM25 and dense retrieval, supply relevant context to a selected language model, and return grounded answers with document and page evidence where available.

03

Provide supporting functions for lecture study

Include document summarisation, question suggestions, cross-document comparison, conversation history, source filtering, and configurable language-model and retrieval settings to support varied study activities.

04

Evaluate the quality of the implemented RAG pipeline

Use generated or prepared question-answer datasets with RAGAS measures—faithfulness, answer relevancy, context precision, and context recall—to identify strengths and weaknesses in both retrieval and answer generation, rather than claim perfect correctness.

Project Scope and Boundaries

A focused lecture-note assistant for students and educators—not a general learning-management platform

In scope

  • Target users: University students (primary) and educators (secondary)
  • Document scope: Text-based PDF lecture notes with managed document collection (view, select, delete)
  • Chunking & indexing: Sentence-aware chunking with source and page metadata; MiniLM embeddings; persistent FAISS index
  • Retrieval: BM25 + dense hybrid retrieval with reciprocal-rank fusion; dense-only fallback when hybrid is unavailable
  • LLM providers: Gemini, OpenRouter, and local models via llama.cpp (availability depends on configuration)
  • Core functions: Grounded chat with citations and source snippets; document summarisation with history; suggested questions; cross-document comparison
  • Management: Conversation and document management; configurable model, temperature, top-k, and embedding settings
  • Evaluation: RAGAS metrics — faithfulness, answer relevancy, context precision, context recall; two-phase workflow (dataset prep + response evaluation)
  • Interface: Web-based UI requiring no ML expertise

Out of scope

  • Non-PDF sources (videos, audio, web pages, e-books)
  • OCR for image-only or scanned PDFs
  • Automatic marking, grading, or student assessment
  • Course-authoring and content-management tools
  • Institution-wide LMS integration
  • Claims of universal subject expertise
  • Replacement of lecturers or human academic support
  • Guarantee of absolute answer correctness
  • Detailed administrative analytics and operational monitoring (supporting modules only)

System limitations

The system is designed as an academic assistance tool, not an authoritative replacement for lecturers, original notes, or independent verification. Retrieval may omit relevant passages; citations indicate supplied evidence rather than guaranteed truth; and language models may still interpret context incorrectly. The project therefore does not guarantee absolute answer correctness.

Research Gap and Project Contribution

Research gap

While existing studies explore RAG retrieval, practical lecture-note assistants still lack a unified workflow that combines: text-specific hybrid retrieval (BM25 + FAISS), configurable local/cloud LLM deployment, transparent source tracing, and an integrated, automated evaluation pipeline.

Project contribution

This project bridges the gap by building an end-to-end, usable prototype: ingesting PDFs with metadata, executing hybrid retrieval with RRF, supporting local and cloud LLMs, and automating RAGAS scoring for robustness.

Contribution is framed as an implementation response—not a claim of universal research novelty.

Evaluation Framework & Model Setup

Four complementary RAGAS dimensions scored on 25 Q&A pairs

Test Data Generation
Qwen 2.5 3B
Generates the 25 Q&A pairs used as evaluation samples.
RAG Inference
Llama 3.2 3B
Retrieves context and generates the final answers for test queries.
Evaluation Judge
NVIDIA Nemotron 3 Ultra
Auto-scoring RAGAS metrics via NVIDIA API as a reference LLM judge.
Faithfulness
Faithfulness = N(supported claims) / N(total claims)
Measures whether the answer is grounded in the retrieved context.
Answer relevancy
Answer Relevancy = CosineSim(Embed(Q), Embed(A))
Assesses how directly the response addresses the user's question.
Context precision
Precision@k = |Retrieved ∩ Relevant| / |Retrieved|
Evaluates the accuracy of the retrieved chunks containing relevant evidence.
Context recall
Recall@k = |Retrieved ∩ Relevant| / |GroundTruth|
Measures if all required evidence was successfully retrieved.

Scores range from 0 to 1; higher is better. Values are summarized on the next slide.

Future Directions & Key Decisions

Embedding Model Selection
Current: all-MiniLM-L6-v2. Trade-off: Upgrading to bge-large boosts recall accuracy but increases memory usage and vector retrieval latency. Needs balance between precision and speed.
Add a Reranker Stage
Current: RRF fusion output. Trade-off: Introducing a dedicated reranker (e.g., Cohere) improves context precision significantly, but adds an extra inference step, impacting real-time response.
LLM Prompt Optimization
Current: Standard system prompts. Trade-off: Optimized prompts can effectively reduce hallucinations by enforcing strict grounding. However, overly rigid prompts may reduce the flexibility and naturalness of the responses.
Upgrade the LLM Model
Current: Gemma / OpenRouter / Local. Trade-off: Stronger models (e.g., GPT-4o) enhance multi-step reasoning capabilities, but drastically increase API costs and local inference latency.

Limitations and Future Work

Current Limitations
  • Text-readable PDFs onlyCurrent system cannot process scanned documents or image-based lecture notes, limiting input scope to digitally generated texts.
  • Evaluation uses 25 question/reference pairsSample size is statistically small; results may not fully generalize across broader course topics.
  • Answer quality depends on retrieved evidence and LLMIf hybrid retrieval misses a crucial chunk, the LLM has no way to infer the correct answer.
  • Local models require suitable hardwareLlama 3.2 3B and embedding models demand GPU resources, making pure local deployment difficult for student laptops.
Future Work
  • OCR and layout-aware parsingIntegrating tools like PaddleOCR to support scanned PDFs, and parsing tables/diagrams as vectorizable text.
  • Broader multi-course evaluation with human reviewExpanding the test set to cover multiple subjects, and incorporating human judgment to validate RAGAS scoring.
  • Tuned reranking and retrieval ablationsConducting systematic ablation studies, introducing a lightweight reranker (e.g., BGE-Reranker) to push context precision further.
  • Expand Studio Panel capabilitiesAdding a summarize module, generate MCQ modules, and other AI-powered tools directly in the Studio Panel to enhance learning workflows.
Roadmap for Production: Addressing these limitations will transition the system from a prototype research tool into a practical, scalable academic assistant for real university courses.
